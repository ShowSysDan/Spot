{{ "Edit" if action else "New" }} Alert Action

Sends a request when an alert is raised (its condition becomes true) and, optionally, another when it clears (false again) — e.g. to turn a warning light on and off or fire a show-control cue.

Destination
UDP is fire-and-forget (broadcast addresses work); TCP connects, sends the message and closes.
HTTP request Any 2xx response counts as delivered; the status code is shown on the Alerts page. Redirects are not followed. The message below is sent as the request body (not for GET); a body starting with { or [ goes as JSON, anything else as plain text.
Placeholders: {% for p in placeholders %}{{ '{' ~ p ~ '}' }}{{ ', ' if not loop.last }}{% endfor %}. {state} is raised/cleared, {on} is 1/0. TCP/UDP messages also understand \r, \n, \t, \0 and \xHH — e.g. end with \r for devices that want a carriage return.
If a send fails
A failure is an HTTP status outside 2xx, a refused or timed-out connection, or a host that doesn't resolve. If the alert changes state while a retry is waiting, the old request is dropped.
